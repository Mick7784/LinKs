# V1.4.11 — Correctif global et import ZIP Amazon automatique

## Import Amazon simplifié

- Choisir le ZIP, cliquer sur « Envoyer », puis consulter le bilan. LinKs identifie les rapports, leurs périodes, leur devise et leur périmètre à partir des informations vérifiables de l'archive.
- Réimports et archives renommées dédupliqués ; vues complémentaires séparées des totaux ; corrections quotidiennes appliquées sans perdre les jours et indicateurs non remplacés.
- Les archives sûres mais ambiguës sont conservées dans « Archives à vérifier », téléchargeables et incluses dans les sauvegardes. Elles ne modifient pas les statistiques.
- Les chevauchements agrégés indécidables restent en attente : aucun prorata, périmètre ni jour à zéro n'est inventé.
- Ventilation par Tracking ID corrigée pour éviter le double comptage des couvertures partielles. Le collecteur manuel vérifie le filtre « tous les Tracking IDs » et la cohérence de ses vues avant enregistrement.

## Corrections de l'audit

- Réponses de mutation envoyées après validation des transactions ; restauration des grandes règles de sources ; limitation des tentatives de connexion indépendante du setup déjà fermé.
- Affiliation : actualisation et navigation fiables même pendant le polling, bilan d'import conservé, partenaire recalculé après sélection d'un doublon.
- Descriptions : association explicite Amazon/Domadoo dans les sous-sections personnalisées ; contradictions entre références produit signalées.
- Statistiques : alias appliqués aux compteurs de campagnes ; Stories PulSe limitées aux sources Instagram reconnues.

## Validation et exploitation

- Validation locale : 468 tests Python dans 44 modules, 71 tests JavaScript/collecteur et sept parcours navigateur ciblés réussis. Les 69 tests Amazon/consolidation rejoués après les derniers ajustements recouvrent en partie ces suites. Les neuf tests de réservation de release passent également.
- Régressions ajoutées au workflow officiel. Playwright de test aligné sur la version déclarée du runtime, Pillow de test fixé et inventaire des versions embarqué dans l'image.
- Publication conditionnée aux tests du workflow, aux contrôles des images AMD64/ARM64 et à la vérification des manifestes de version et latest.
- Pas de migration de table ni de reclassement des données financières existantes. Conserver le volume /data, la configuration et les sauvegardes de l'instance lors de la mise à jour.
- Les tests utilisent des données synthétiques : les variantes d'exports et l'authentification sur les comptes réels restent à vérifier. La collecte Amazon quotidienne reste désactivée.
- La publication GitHub/GHCR et la mise à jour de l'instance hébergée sont deux étapes distinctes.
